# STEM101 상세 시뮬레이션 디자인 시스템

## 1. 한 문장 원칙

STEM101의 상세 페이지는 학생과 선생님이 함께 만든 **과학 관측 도구**처럼 보여야 하며, 사용자가 변수를 바꾸고 결과를 검증하는 흐름이 장식이나 설명보다 먼저 보여야 한다.

이 문서는 조석 시뮬레이션에서 검증된 화면 규칙을 모든 수학·과학 시뮬레이션에 공통 적용하기 위한 기준이다. 프로젝트 목록 페이지에는 적용하지 않는다.

## 2. 공통 경험 구조

상세 페이지는 가능한 한 다음 순서를 유지한다.

1. **짧은 제목과 현재 상태**: 무엇을 관찰하는지, 실행 중인지 즉시 알 수 있다.
2. **관점·표현 방식 전환**: 관찰 기준, 학습용/실제 비율, 비교 모드를 한곳에서 바꾼다.
3. **주 시뮬레이션 장면**: 첫 화면에서 가장 큰 면적을 차지한다.
4. **재생·시간 조작**: 재생, 일시정지, 속도, 초기화를 한 줄의 전송 제어처럼 배치한다.
5. **변수 제어**: 원인이 되는 입력을 논리적 묶음으로 제공한다.
6. **현재 결과**: 수치, 방향, 상태를 입력 변화와 동시에 갱신한다.
7. **비교·기록**: 그래프, 표, 궤적 또는 이전 실행과의 비교로 예상이 맞았는지 확인한다.
8. **모형 설명과 한계**: 과장된 표현, 생략된 변수, 실제 현상과의 차이를 짧고 명확하게 밝힌다.

모든 주제가 모든 영역을 가져야 하는 것은 아니다. 다만 `조작 → 변화 → 검증`의 연결은 반드시 화면에서 보이게 한다.

## 3. 시각 언어

### 과학 관측 도구의 인상

- 장면과 데이터가 주인공이다. 페이지 소개나 홍보 문구가 첫 화면을 차지하지 않는다.
- 넓은 캔버스, 얇은 구분선, 각진 제어 장치, 단정한 숫자 표기를 사용한다.
- 패널을 여러 겹의 카드로 감싸지 않는다. 캔버스, 레일, 밴드, 표처럼 역할이 분명한 면을 사용한다.
- 그림자와 광택은 상태나 깊이를 구분할 때만 약하게 사용한다.
- 숫자·시간·단위는 고정폭 글꼴을 사용해 변화량을 읽기 쉽게 한다.

### 글자 크기와 밀도

- 본문과 주요 제어: 데스크톱 최소 `14px`, 모바일 최소 `15px`.
- 보조 라벨: 최소 `12px`. 반드시 중요도가 낮은 정보에만 사용한다.
- 터치 대상: 최소 `44 × 44px`.
- 한 제어 안에는 이름, 값, 단위만 둔다. 긴 원리 설명은 현상 주석이나 하단 설명으로 분리한다.
- 천체나 물체 라벨은 `지구`, `달`처럼 짧게 쓴다. `지구 주위 공전` 같은 관계 문구를 물체에 붙이지 않는다.

## 4. 프로젝트별 두 색상 규칙

각 상세 프로젝트는 다음 두 색상을 반드시 선언한다.

| 역할 | 토큰 | 용도 |
| --- | --- | --- |
| 주색 | `--sim-color-primary` | 배경, 넓은 면, 깊이, 프로젝트의 기본 분위기 |
| 부색 | `--sim-color-secondary` | 선택, 포커스, 조절 결과, 핵심 데이터와 변화 |

조석 시뮬레이션의 기준 쌍은 깊은 차콜 `#071018`과 조석 시안 `#53D6DF`다. 화면에서 느껴지는 검정·회색 계열의 관측실 분위기는 주색과 공용 중립색으로 만들고, 시안은 상호작용과 물의 변화를 읽는 데 사용한다.

색상 선택 규칙:

- 두 색은 프로젝트의 현상에서 연상되는 이유가 있어야 한다.
- 기존 프로젝트와 동일한 두 색 조합을 재사용하지 않는다.
- 배경·표면·선·본문용 중립색은 공용 토큰을 쓴다. 중립색은 프로젝트 대표 색상 수에 포함하지 않는다.
- 경고, 오류, 성공처럼 의미가 고정된 색은 공용 의미색을 쓴다. 의미색을 장식이나 선택 상태에 쓰지 않는다.
- 부색 하나만으로 상태를 전달하지 않고 텍스트, 모양, 선 종류를 함께 바꾼다.
- 부색과 사용 면의 명암 대비는 일반 텍스트 `4.5:1`, 큰 텍스트와 UI 경계 `3:1` 이상을 목표로 한다.

새 주제 예시는 방향만 참고하고 실제 등록 색상은 겹치지 않게 조정한다.

| 주제 성격 | 주색 방향 | 부색 방향 |
| --- | --- | --- |
| 역학·운동 | 짙은 남색 | 선명한 주황 |
| 전기·자기 | 짙은 보라 | 밝은 연두 |
| 화학 반응 | 짙은 청록 | 따뜻한 노랑 |
| 생명·생태 | 짙은 녹색 | 산호색 |
| 수와 기하 | 먹색 보라 | 밝은 라임 |

## 5. 공통 토큰과 구성요소

`shared/simulation-ui.css`는 프로젝트 색상 두 개를 받아 파생 표면과 상태를 만든다. 새 페이지에서는 `<main class="sim-shell">`에 두 토큰을 선언한다.

```html
<main
  class="sim-shell"
  data-stem-simulation
  style="--sim-color-primary: #161d3a; --sim-color-secondary: #ff9f43"
>
```

공통 클래스의 역할:

- `.sim-header`: 짧은 제목, 상태, 목록으로 돌아가기.
- `.sim-toolbar`: 관점·표현·비교 모드.
- `.sim-workspace`: 주 캔버스와 제어 레일.
- `.sim-stage`: 시뮬레이션이 그려지는 가장 큰 영역.
- `.sim-transport`: 재생, 시간, 속도, 초기화.
- `.sim-controls`: 변수를 묶는 제어 레일.
- `.sim-readout`: 현재 수치나 판정.
- `.sim-evidence`: 그래프, 표, 실행 기록.
- `.sim-note`: 모형의 가정과 한계.

프로젝트 프레임워크에 맞춰 컴포넌트로 나누되, 같은 역할의 요소는 같은 토큰과 상태 표현을 사용한다.

## 6. 시뮬레이션 상호작용 규칙

### 장면 탐색

- 휠 확대는 화면 중앙이 아니라 **마우스 포인터가 가리킨 세계 좌표**를 고정점으로 삼는다.
- 드래그는 장면 이동, 직접 조작 대상의 드래그는 대상 이동으로 구분하고 커서와 안내 문구로 알린다.
- 실제 축척처럼 범위가 큰 장면에는 화면 아래쪽에 고정 미니맵을 둔다. 미니맵은 전체 범위, 현재 뷰포트, 주요 대상 위치를 동시에 보여준다.
- `전체`, `대상 A 가까이`, `대상 A–B 거리`, `크기 비교` 같은 프리셋은 자유 탐색을 대신하지 않고 빠른 출발점으로만 제공한다.
- 실제 축척과 학습용 과장 표현을 섞지 않는다. 모드 이름과 현재 축척을 항상 표시한다.

### 라벨과 주석

- 라벨은 물체 중심에서 최소 한 글자 높이 이상 떨어뜨린다.
- 두 물체가 가까워지면 라벨 후보 위치를 위·아래·좌·우 순서로 평가해 겹치지 않는 곳에 둔다.
- 멀어진 라벨은 얇은 리더선으로 대상과 연결한다.
- 라벨 충돌을 해결할 수 없으면 우선순위가 낮은 보조 설명을 숨기되 물체 이름과 핵심 값은 유지한다.
- 패널과 미니맵은 처음부터 최종 위치에 존재해야 한다. 화면 중앙에서 날아오거나 장면을 가리는 등장 애니메이션을 사용하지 않는다.

### 학습용 과장과 실제 비교

- 보이지 않는 변화는 과장할 수 있지만 배율과 이유를 바로 옆에 쓴다.
- 실제 크기·거리 모드는 같은 축척을 유지한다. 보이지 않을 정도로 작은 대상은 확대창, 윤곽 참고선, 미니맵으로 보조하고 본체 크기를 몰래 키우지 않는다.
- 비교용 윤곽은 낮은 불투명도와 점선으로, 실제 대상은 높은 대비와 실선으로 구분한다.
- 힘이나 비율은 기준값을 명시한다. 예: `달 = 1.00`, `태양 = 0.46`.

## 7. 반응형·접근성

- 넓은 화면은 `캔버스 + 제어 레일`, 좁은 화면은 `캔버스 → 핵심 제어 → 결과 → 세부 제어` 순서로 쌓는다.
- 작은 화면에서도 캔버스를 먼저 볼 수 있어야 하며, 제어 패널 때문에 장면이 사라지지 않게 한다.
- 키보드 포커스는 부색 윤곽선으로 분명하게 표시한다.
- 재생 중 움직임은 `prefers-reduced-motion`에서 정지하거나 완화한다.
- 모든 입력은 보이는 이름과 단위를 갖고, 아이콘만 있는 버튼은 접근 가능한 이름을 제공한다.
- 그래프의 색 구분은 선 종류, 마커, 직접 라벨을 함께 사용한다.

## 8. 문장과 설명의 목소리

- 짧고 관찰 가능한 문장을 쓴다: `각도를 올리면 최고점은 어떻게 달라질까?`
- 결과를 먼저 단정하지 말고 사용자가 예상하고 확인하게 한다.
- 전문 용어는 숨기지 않되 화면 가까이에 쉬운 뜻을 붙인다.
- 광고성 표현, 성취 과장, 불필요한 감탄문을 쓰지 않는다.
- `정답`보다 `현재 조건`, `예상`, `관찰 결과`, `왜 다를까?`, `모형의 한계`를 사용한다.

## 9. 새 상세 페이지 체크리스트

- [ ] 프로젝트 전용 주색과 부색을 정했고 카탈로그에 기록했다.
- [ ] 기존 프로젝트와 같은 색상 쌍이 아니다.
- [ ] 첫 화면에서 시뮬레이션 장면과 핵심 조작이 보인다.
- [ ] 사용자가 바꿀 변수와 즉시 변하는 결과가 연결되어 있다.
- [ ] 예상과 결과를 비교할 수치·그래프·기록 중 하나가 있다.
- [ ] 실제값과 시각적 과장을 구분해 표시한다.
- [ ] 라벨이 대상과 서로를 가리지 않는다.
- [ ] 확대, 이동, 초기화, 미니맵이 필요한 범위에서 작동한다.
- [ ] 본문 14px, 보조 라벨 12px, 터치 대상 44px 기준을 지킨다.
- [ ] 키보드, 작은 화면, 모션 감소 설정을 확인했다.
- [ ] 모형이 설명하지 못하는 것을 적었다.
- [ ] `node scripts/validate-catalog.mjs`를 통과했다.
