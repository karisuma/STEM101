# STEM101 제작형 수업 가이드

## 수업의 정체성

STEM101은 완성된 시뮬레이터를 학생에게 보여주는 학습자료 모음이 아닙니다.
학생과 선생님이 같은 제작자가 되어 질문을 코드로 표현하고, 실행 결과를 테스트하며 수학·과학 원리를 이해하는 바이브코딩 수업입니다.

```text
질문하기 → 바이브코딩 → 테스트하기 → 설명하기
                  ↑          ↓
                  └── 수정하기 ┘
```

## 수업에서 함께 만드는 것

- 현상에서 출발한 탐구 질문
- 결과를 예상할 수 있는 간단한 가설
- 변수를 직접 조절하는 인터랙티브 시뮬레이터
- 예상과 실제 결과를 비교하는 테스트
- 실패와 수정 과정의 기록
- 발견한 원리에 대한 학생의 설명

## 역할

### 학생

- 궁금한 점을 질문으로 바꿉니다.
- 어떤 값을 바꿀 수 있어야 하는지 제안합니다.
- AI와 대화하며 화면과 동작을 만듭니다.
- 실행 결과가 예상과 같은지 테스트합니다.
- 결과와 수정 이유를 자신의 말로 설명합니다.

### 선생님

- 정답이나 완성 코드를 먼저 제시하지 않습니다.
- 질문을 테스트 가능한 형태로 다듬도록 돕습니다.
- 과학적·수학적으로 잘못된 가정을 확인합니다.
- 테스트 조건과 비교 방법을 함께 설계합니다.
- 결과보다 학생의 판단과 수정 과정을 관찰합니다.

## 프로젝트 난이도

| 단계 | 제작 과제 |
| --- | --- |
| 시작 | 하나의 변수를 조절하고 눈에 보이는 변화를 구현 |
| 발전 | 여러 변수의 관계를 구현하고 예상 결과와 비교 |
| 도전 | 모형의 한계를 찾고 더 나은 계산이나 표현으로 수정 |

## 프로젝트 필수 요소

각 프로젝트에는 다음 항목이 있어야 합니다.

- `index.html`: 실행 가능한 시뮬레이터
- `project.json`: 학년, 과목, 질문, 제작 단계, 테스트 기준
- `README.md`: 아이디어, 프롬프트, 구현 과정, 원리, 모형의 한계
- 사용자가 바꿀 수 있는 변수와 즉시 확인 가능한 결과
- 최소 한 가지 예상 결과와 이를 확인하는 테스트
- 프로젝트 목록으로 돌아가는 링크
- 키보드와 모바일 화면 대응

## 좋은 테스트 질문

- 이 값을 두 배로 바꾸면 무엇이 달라져야 하나요?
- 두 조건이 같을 때와 반대일 때 결과는 어떻게 달라야 하나요?
- 코드가 보여주는 결과가 실제 원리와 일치하나요?
- 예상과 다른 결과가 나온 이유는 계산, 표현, 가정 중 무엇인가요?
- 이 시뮬레이터가 설명하지 못하는 실제 현상은 무엇인가요?

## 보호자가 볼 수 있는 가치

완성 화면의 화려함보다 학생이 어떤 질문을 했고, 무엇을 테스트했으며, 실패 후 어떤 판단으로 수정했는지를 봅니다. 결과물을 설명하는 과정에서 개념 이해와 문제 해결 방식이 함께 드러납니다.
